# 数据库来源连接器

researchmesh/connectors/database.py 实现只读数据库出口（见 docs/来源协议.md）的采集连接器。连接器用只读 URI 与显式读事务访问出口，不能修改来源；全部连接器状态保存在研合库内，不依赖生产凭据，本地 SQLite 即可复现。

## 两阶段采集

1. 快照：在同一读事务中读取 MAX(txid) 作为边界，并读取 institutions、achievements、people、authors 四张表。WAL 下读取期间的并发提交对快照不可见；`during_read` 钩子可在读事务建立后注入并发提交用于演练。快照内容整批写入研合（一个 generation），同时把四张表原样复制进连接器镜像（connector_institutions 等表），检查点设为边界事务号。
2. 增量：poll 读取 txid 大于检查点的 transactions 与 changes，按 txid、ordinal 顺序逐笔应用。每笔源事务在一个研合事务内完成：校验 before_json 与镜像一致、按日志重放进镜像、由镜像推导全部成果记录、以 complete 快照推进一个 generation、写检查点与账本。任何一环失败，整笔回滚，镜像与研合记录保持不变。

## 语义

- 事务原子性：一笔源事务可能改机构并调整多条成果关联；研合侧要么整笔生效（同一 generation），要么在 connector_state 与账本中保留失败原因（状态 failed），不会暴露半个关系变更。后续事务不再尝试，直到显式 rebuild。
- 关系删除不等于成果删除：authors 删除只更新成果的人员列表；只有 achievements 删除才把对应来源项撤回（active=0 并移出匹配索引）。
- 机构改名：institutions 变更会重推所有引用该机构的成果记录；人员改名同理。人员顺序按 authors.ordinal 显式序位保留在镜像与 lineage 输出中（研合匹配契约把人员作为集合处理）。
- 外部身份：研合记录键为 source:成果主键，不用标题或行号；主键不复用时记录身份稳定。映射规则版本 MAPPING_VERSION 记入状态与账本。
- 溯源：connector_ledger 记录每笔事务号、generation、结果摘要与受影响成果；connector_achievements.txid 记录每成果最后变更事务；lineage 可由记录键追到源表主键、事务号与映射版本。

## 检查点与恢复

- 检查点只确认已完整提交到研合的源事务。重启后 poll 跳过已应用事务，批次幂等，不产生额外版本。
- 日志缺口：retention.first_tx 越过 checkpoint+1（或事务编号不连续）时进入 needs_rebuild 并记录原因；旧来源记录保持可用、可继续发布。rebuild 重新取一致快照，通过 sources 的 generation 检查后原子切换，检查点跳到新边界。
- 人工导入或词典变化：sources 的 generation 检查使连接器在来源被外部写入时立即失败（conflict），不会覆盖人工版本；词典变化后 require_index 阻止过期索引参与发布，显式 reindex 后恢复，status.index_stale 可观测。

## 操作

connector.snapshot(source, path) 初始化（要求来源无既有记录）；connector.rebuild(source, path) 显式重建切换；connector.poll(source, path) 增量衔接；connector.status(source, path=None) 状态与待办；connector.lineage(source, achievement=None) 溯源；connector.ledger(source) 事务账本；connector.verify(source) 核对镜像、记录、账本与索引一致性。python3 -m researchmesh rehearse 依次演练并发快照、多表事务、关系删除、成果删除、日志缺口重建、重启幂等、词典与人工导入冲突、失败事务回滚。

## 限制

成果主键须满足研合标识符字符集，kind 须使用研合词表，否则对应事务失败并保留原因。镜像忠实复制出口四表（含悬挂关系），推导时按连接语义忽略无成果的关系；成果引用了不存在的机构或人员时事务失败。每个来源应由单个连接器写入口径管理，人工写入同一来源会触发 conflict 并需要显式 rebuild 取舍。
